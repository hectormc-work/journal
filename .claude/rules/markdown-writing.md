General principles for writing markdown in this repo.

## Voice

Write like me, not like a corporate wiki.

- Fairly casual, not corporate or formal
- No em dashes, ever
- Human readable, plain language over jargon

## Structure

Skimmable over readable-prose.

- Bullets, not paragraphs
- Use headers, not one flat bullet list
  - Sections and subsections (`##`/`###`) so I can scan and jump around
  - Open each section with a very short sentence to orient, before the bullets start
- Nest sub-points under the principle they belong to, instead of a flat list or an inline explanation
- Lean and skimmable
- Dense wording: don't linger on the stumble or incident that prompted a piece of writing, write the larger principle instead

## Repetition

Some overlap between docs is fine. Unclear overlap is not.

- Consider if repeating is necessary here
- If repeating: cross-reference to make it clear
- Make the one narrower in scope go into greater detail
